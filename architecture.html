Multi-Agent Clinical Triage Pipeline

End-to-End AI Triage Flow

From raw patient JSON to matched doctor and multi-view reports. Each step below is clickable — collapse/expand details as you walk through the pipeline.

Engine / Infra
1
Step 1
Patient Data Input
JSON → Validated Patient Object
OUTPUT: structured patient data
  • Load patient information from JSON payload.
  • Validate presence of required fields (demographics, contact, complaint, etc.).
  • Parse symptoms and medical history into a clean internal schema.
Structured Output
patient_id, demographics, symptoms[], history[], meds[], allergies[]
2
Step 2 · AI Agent 1
Gemini Symptom & Specialty Analysis
Gemini – Clinical Reasoner
OUTPUT: specialty, conditions, reasoning, red_flags
  • Comprehensive analysis of symptoms and medical history in context.
  • Identify most relevant medical specialty (or multiple candidate specialties).
  • Recognize potential conditions and differentials.
  • Detect clinical red flags requiring higher caution.
  • Recommend appropriate diagnostic tests or baseline workup.
Structured Output
specialty, candidate_specialties[], conditions[], reasoning_text, red_flags[], recommended_tests[]
3
Step 3 · AI Agent 2
Grok Urgency Assessment
Grok – Triage & Risk
OUTPUT: urgency_score, risk_level, time_to_treatment
  • Compute urgency score on a 0–100 scale based on symptom severity and red flags.
  • Map score to human-friendly risk levels (e.g., low / moderate / high / critical).
  • Highlight any critical red-flag combinations.
  • Estimate recommended time window for medical attention.
Structured Output
urgency_score (0–100), risk_level, category, critical_flags[], time_to_treatment
4
Step 4 · AI Agent 3
O4-Mini Final Evaluation
O4-Mini – Arbiter & Planner
OUTPUT: final_specialty, confidence, action_plan
  • Cross-validate Gemini (analysis) and Grok (urgency) outputs for consistency.
  • Resolve conflicts in recommended specialties or conditions.
  • Generate a consolidated, patient-oriented action plan.
  • Attach confidence scores to the final recommendation.
Structured Output
final_specialty, final_conditions[], confidence_scores{}, unified_action_plan, notes_for_doctor
5
Step 5
Doctor Matching (8-Factor Algorithm)
Matching Engine
OUTPUT: matched_doctor, score, quality, explanation
  • Load doctor profiles from specialty-specific JSON datasets.
  • Compute an 8-factor compatibility score per doctor (experience, outcomes, distance, rating, language, etc.).
  • Apply sub-specialization matching (e.g., pediatric cardiology vs. general cardiology).
  • Prioritize based on urgency: faster access for higher-risk cases.
  • Adjust for age-appropriate care (pediatric, adult, geriatric).
  • Select best match and generate an explanation of why this doctor was chosen.
Structured Output
matched_doctor{id, name, specialty, subspecialty}, score, quality_band, explanation_text, alternatives[]
6
Step 6
Report Generation
Multi-Audience Reporting
OUTPUT: Patient / Doctor / Admin PDFs + JSON
  • Create patient-facing PDF in simplified, non-technical language.
  • Generate doctor PDF with clinical details, reasoning, and red-flag trail.
  • Generate admin PDF with a consolidated overview across all agents.
  • Emit JSON data files for downstream analytics & storage.
Artifacts
patient_report.pdf, doctor_report.pdf, admin_summary.pdf, triage_case.json, logs_ai_agents.json
7
Step 7
Result Compilation & Storage
Final Assembly
OUTPUT: complete triage result object
  • Compile all step outputs into a single unified triage structure.
  • Persist canonical JSON for record-keeping and audit.
  • Return final triage result to the calling application / API.
Final Object
triage_case{ patient_data, gemini_analysis, grok_urgency, o4_final_eval, doctor_match, reports[], metadata }
